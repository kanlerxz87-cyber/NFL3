Findings and required follow-up

SRC-01 · HighConfirmed by offline synthetic tests

Source-host checks are not independent of the data being checked

`official_hosts(snapshot)` adds hosts from `depth_rows` and `depth_directory_successes`; `verify_lab()` then accepts a depth row when its host is in that same set. A synthetic `untrusted.invalid` host is admitted. Separately, `capture_official.py` adopts matching hostnames from the team-directory HTML and creates its redirect allowlist from the discovered hostname; a synthetic directory entry was accepted. Add a static 32-club host map before either gate. These are verifier design gaps, not evidence that current club hosts are malicious.

SRC-02 · HighConfirmed by offline synthetic test

The depth-row check does not require HTTPS

The existing depth-row gate compares only `urlparse(source_url).hostname` against an allowlist; an HTTP URL on an allowed hostname passes that part of the check. The independent fixed allowlist rejects HTTP.

SRC-03 · HighConfirmed by offline synthetic test

The broad repo audit can treat unrelated GitHub repositories as official

`github.com` is in the broad `EXTRA_OFFICIAL` host set, while `is_community()` only excludes two nflverse path prefixes. A test URL under an unrelated GitHub owner is therefore eligible to count as an official table citation. GitHub hosting/digests establish neither NFL authorship nor NFL factual authority.

What this audit does not establish

  • This run does not fetch or re-open NFL/club pages. Links are provided for manual review; availability and page contents may change.
  • An approved hostname proves only the publisher domain, not that a linked page supports the specific claim or that the extracted row is parsed correctly.
  • SHA-256 checksums support byte-integrity comparisons only; they do not prove NFL authorship, truth, license, or currentness.
  • The static club-domain map is a review aid based on the official NFL team directory URL in catalog source S05; verify it again when updating the map.
  • The historical snapshot timestamp is not a live injury/depth feed or a guarantee about current lineups; this HTML/report is generated from the checked-in snapshot and is not refreshed automatically by the Pages deployment capture step.
  • No odds/proposition ledger, validated strategy edge, empirical parlay correlation, or funded reward result is established by this audit.
