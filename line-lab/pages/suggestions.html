Suggestions

18 proposals, scored and stated with their trade-offs, so a path can be chosen before anything is implemented.

This page exists so that nothing gets built by default

Every proposal below is scored on four axes and carries an explicit recommendation. Nothing is implemented because it was suggested — implementation status is tracked separately and shown as state. Review it, compare the trade-offs, then choose.

Review protocol

  1. 1. Anyone can add a suggestion in state 'proposed'. It must name the problem, the evidence and what would make it wrong.
  2. 2. 'under review' means the operator has read it and requested missing information; the open questions are linked by id.
  3. 3. A suggestion is 'accepted' only when its decision criteria are written down and the blocking questions are answered or explicitly waived.
  4. 4. 'rejected' and 'deferred' keep their reason. Nothing is deleted — a rejected idea that returns is a signal about the process.
  5. 5. 'implemented' requires the verification gate to pass on the build that ships it.
  6. 6. Only one P0-scope change may be in flight at a time, because the P0 items are all data-layer changes that collide.

Scoring

Four declared inputs, one ratio, and the formula is printed on every row so it can be argued with:

score = impact × confidence ÷ ( effort × (1 + 0.25 × risk) )

What the score does not capture: dependency chains and sequencing. SG-01 scores 6.67 and ranks last, yet it blocks every other measurement on this site. Critical-path items are flagged in the table and called out on the dashboard rather than allowed to sink. Impact and confidence are about decision quality. Effort is 1 for a single sitting of scripted work and 5 for weeks or a purchase. Risk counts the damage if the idea is wrong — a proposal that could produce confidently wrong signals scores 5.
