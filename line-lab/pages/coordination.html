Coordination

The shared task board, the claim protocol, and what was verified under each task.

Single-session run, multi-session protocol

COORDINATION.md is the shared task board: 13 tasks, each with an owner, a branch, a file scope and a status. It was written and pushed before any work began, so a parallel session would have seen the claim.

No other session, branch or claim existed at the start of this run, so this session performed every task and also acted as the final integration session. The protocol for splitting the work across sessions is documented in the file and is unchanged.

What the board records

  • Claims before work. Session id, branch and file scope, committed and pushed before editing.
  • Non-overlapping scopes. Shared outputs — the data files, navigation and this site's build — are integration-only.
  • Handoff rule. A claim older than 60 minutes with no commits may be taken over, with the handoff logged.
  • Verification log. Per task: sources used, the check performed, and any irregularity found.
  • Requests, not edits. If a task needs another session's file, the request is logged rather than the file touched.
