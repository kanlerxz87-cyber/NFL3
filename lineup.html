Availability intelligence

Lineups & injury tracking

Evidence-first design

A useful lineup model must distinguish an injury report from confirmed availability, confirmed active status from expected workload, and a listed replacement from proven role. No current player statuses or lineups are replicated here because they change and this project has no automated, timestamped feed.

Do not infer depth from an injury listing. The official report is useful evidence of report status, but the available source does not by itself confirm the replacement's string rank, assignment, snaps, matchup or expected workload. Those fields stay blank until a dated source supports them.

Coverage rules to implement

Offense

Track QB, offensive-line positions, skill players and confirmed role/participation separately. Do not convert “starter out” into a fixed points adjustment without a tested historical estimate.

Defense

Track position-group absences and replacement participation. Defense-level weakness needs outcome evidence and opponent-adjusted comparisons, not a roster label.

Late changes

Save multiple snapshots. If a report or lineup changes after a forecast, preserve both the original forecast and a separately timestamped update.

Automation must-haves

  • Poll an authorized source on a declared schedule and store immutable raw payload + retrieval time.
  • Normalize team/player identifiers but preserve original source values and an auditable mapping.
  • Distinguish “not listed,” “not yet published,” “not available,” and “source fetch failed.”
  • Require human-review flags for ambiguous names, stale data, conflicting team sources, missing depth rank and status changes near kickoff.
  • Do not display an injury-based line adjustment unless data freshness, evidence provenance and model-validation checks pass.
