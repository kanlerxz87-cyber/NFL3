Suggestions & decision paths

Every proposed improvement, in one reviewable place, with the trade-off it accepts and the official source that grounds it — so a path can be chosen before anything is built.

How to use this page. This is the review board. Nothing here has been implemented. Read the paths, mark the ones you want, and the implementation follows the marked order. Every suggestion names the official source that grounds it and the trade-off it accepts.
01 / REVIEW FLOW

How a suggestion becomes work

Accept, defer or reject — with a reason.

Step 11 · Read the flagOpen the flagged item and its official source link. The link is the starting point for investigation, not a certificate that the answer is there.
Step 22 · Check the registerLook for the matching question in the questions register. A flag without a registered question is a new item that should be added.
Step 33 · Choose a pathMark a suggestion as accept, defer or reject with a reason. Implementation starts only after that mark exists.
Step 44 · Record the decisionOpen a change request on the repository with the flag ID, the source that closes it and the expected effect on the affected tables.
Step 55 · Re-verifyThe next deployment re-captures the official sources and re-runs the verification. The flag stays published until the evidence supports closing it.
